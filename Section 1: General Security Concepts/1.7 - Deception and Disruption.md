# 🍯 Honeypots, Honeynets & Honeytokens

Security isn’t only about blocking attackers — sometimes it’s about **tricking them**.

---

## **Honeypots**
- Fake systems made to **attract attackers**
- Let attackers interact so we can see:
  - What tools they use
  - What systems they try to attack
- Usually **not real production systems**
- Often target automated attacks (bots)

---

## **Why Use Honeypots?**
- Learn attacker behavior
- Keep attackers busy
- Protect real systems by distracting them

---

## **Honeynets**
- A group of honeypots working together
- Can include:
  - Servers
  - Workstations
  - Routers
  - Firewalls
- Looks like a real network
- More believable → attackers stay longer

---

## **Honeyfiles**
- Fake files that look important
- Example:
  - `passwords.txt`
- Should **never** be accessed in normal use
- If accessed → alerts are triggered
- Helps detect intruders already inside the system

---

## **Honeytokens**
- Fake but **traceable data**
- Used to detect data leaks

### Examples:
- Fake API keys
- Fake email addresses
- Fake database records
- Tracking pixels or cookies

If these show up elsewhere:
- You know data was copied
- You know where it came from

---

## **Key Idea**
Honeypots, honeynets, honeyfiles, and honeytokens:
- Do **not** stop attacks directly
- Help detect, study, and track attackers
- Add deception to your security strategy
